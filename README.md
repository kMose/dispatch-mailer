# Dispatch

A single-account, spreadsheet-driven mailer for Windows, macOS and Linux.

One operator, one SMTP account, one list at a time. Dispatch reads an `.xlsx`, decides
who is eligible, sends personalised mail at a human pace, writes the send date back into
the spreadsheet, and watches IMAP for replies and bounces.

**Dry run is the default.** Nothing leaves the machine until you both set
`safety.dry_run: false` in `campaign.yaml` *and* confirm a run in the UI.

---

## Install

Requires Python 3.11+ (developed and tested on 3.14).

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -e ".[dev]"
```

Run the desktop app:

```bash
python -m dispatch
```

Run the headless CLI:

```bash
dispatch --help
```

No config yet? `python -m dispatch` opens a three-step wizard: choose spreadsheet →
choose provider + account (password goes to the OS keyring) → pick a starter template.
It writes `campaign.yaml` and `templates/` beside your spreadsheet.

`campaign.yaml` is deliberately **not** committed (it holds machine-specific paths and
provider hosts). For a fresh clone, either run the wizard or:

```bash
cp campaign.example.yaml campaign.yaml   # then edit hosts/addresses
```

Or bootstrap from the CLI:

```bash
dispatch init --dir ./my-campaign      # writes campaign.yaml + templates + sample leads.xlsx
```

### Running the packaged app on Windows

Double-click **`Run Dispatch.cmd`** in the campaign folder. It starts
`dist\Dispatch\Dispatch.exe` with `campaign.yaml` passed explicitly, so it works no matter
what the current directory is.

Equivalently, from a terminal:

```bat
cd "C:\path\to\campaign"
dist\Dispatch\Dispatch.exe "C:\path\to\campaign\campaign.yaml"
```

Don't double-click `Dispatch.exe` by itself on first use: Windows makes its working
directory `dist\Dispatch`, so it cannot see `campaign.yaml` and opens the setup wizard.
After one successful start Dispatch remembers the last campaign in the registry, so a
plain double-click then reopens it. Only one copy can run at a time — a lock stops two
windows writing the same spreadsheet.

### One-command demo (safe)

```bash
dispatch init --dir demo
python - <<'PY'
import pathlib, yaml
p = pathlib.Path("demo/campaign.yaml"); d = yaml.safe_load(p.read_text())
d["campaign"]["send_window"]["enabled"] = False
d["campaign"]["quota"] = 4
p.write_text(yaml.safe_dump(d, sort_keys=False))
```

## First-run checklist

1. **Spreadsheet** — `.xlsx` with a header row and an `Email` column. Keep a backup.
2. **Provider hosts** — set `sender.smtp.host` / `sender.imap.host` (the wizard presets
   Gmail, Microsoft 365, Outlook.com, Fastmail, Zoho, iCloud).
3. **Password** — Settings → Sending account → *Save password to OS keyring*.
   On Gmail this must be a 16-character **App Password**, not your login password.
4. **Compliance footer** — set a real postal address and unsubscribe URL/host in
   Settings → Compliance. The footer is generated by the program and cannot be removed
   by a template.
5. **Validate** — `dispatch validate --config campaign.yaml`, or Campaign → Pre-flight.
6. **Dry run** — `dispatch send --config campaign.yaml --dry-run`. Open a few `.eml`
   files in `./outbox/` and check them in a real mail client.
7. **Send test to myself** — Template builder → *Send test to myself* (uses the real
   account and is never suppressed by dry run). Dry run is a *rehearsal*: it obeys the
   same throttle, window and caps as a live run, so a 200-send dry run at 60–260s takes
   about as long as the real thing. For a quick smoke test set `throttle.mode: fixed`
   and `throttle.fixed_seconds: 0` (and disable the send window) in the config.
8. **Go live** — set `safety.dry_run: false` (or untick dry run in Settings), review the
   pre-flight arithmetic, then start. Over 50 sends you must type `SEND <n>`.
9. **After the run** — the post-run report shows totals and a per-hour breakdown. Use
   *Write results to sheet* to preview the diff and then write it. `LastAdvertised`,
   `Replied`, `Status`, `LastError` and `Attempts` are updated; replies detected by IMAP
   are written to the `Replied` column on the same flush.

## CLI

```bash
dispatch validate    --config campaign.yaml [--quota N]
dispatch send        --config campaign.yaml [--dry-run] [--quota N] [--yes]
dispatch export      --config campaign.yaml --out results.csv [--run-id N]
dispatch sync-inbox  --config campaign.yaml
dispatch flush       --config campaign.yaml [--run-id N] [--dry-run]
dispatch init        [--dir DIR] [--force]
dispatch template    new|preview|validate|list --config campaign.yaml
```

`validate` exits `0` when the run is feasible and `1` when it is blocked (no sheet,
locked sheet, no eligible contacts, quota not fitting the window).

`send` refuses to send live without confirmation: interactive runs ask you to type
`SEND <n>` above the threshold; non-interactive runs require `--yes`.

## Configuration (`campaign.yaml`)

Paths are resolved relative to the config file.

| Key | Meaning |
|---|---|
| `campaign.name` | Shown in the UI and the unsubscribe footer |
| `campaign.sheet_path` / `sheet_tab` | Workbook and optional tab (`null` = active) |
| `campaign.date_order` | `DMY`, `MDY` or `ISO` (see *Dates* below) |
| `campaign.quota` | Maximum sends in one run |
| `campaign.frequency_days` | Re-contact gap; eligible when `gap >= frequency_days` |
| `campaign.shuffle_order` | Randomise the queue |
| `campaign.send_window` | `enabled`, `start`, `end`, `days`, `timezone` |
| `throttle.mode` | `fixed` or `random` |
| `throttle.fixed_seconds` / `random_seconds` | Send-to-send interval |
| `throttle.backoff_seconds` | Soft-failure backoff ladder |
| `limits.daily_cap` / `hourly_cap` | Per-account caps; daily resets at local midnight |
| `safety.dry_run` | **Default true.** Must be false for real mail |
| `safety.require_typed_confirmation_over` | Typed confirmation threshold |
| `safety.stop_on_failure_rate` | Stop when the recent failure rate exceeds this |
| `warmup.enabled` / `ramp` | Weekly ceiling; effective cap = `min(daily_cap, ramp[week])`. Before the first send the clock is at week 0, so `ramp[0]` applies |
| `sender.*` | From name/address, Reply-To, SMTP, IMAP, `secret_ref` |
| `template.kind` | `blocks` or `raw` (inferred from the `.json` if absent) |
| `template.subject` | Subject template with placeholders |
| `template.html_path` / `text_path` / `blocks_path` | Rendered artifacts + block source |
| `template.footer.*` | Postal address, unsubscribe URL (`{token}`), mailto |

### Secrets

`secret_ref` defaults to `keyring:dispatch/sam` (service/username). The password is read
from the OS keyring at send time and never written to YAML, SQLite, logs or `.eml` files.
`env:VAR` is accepted for headless test rigs only.

### Provider presets

The setup wizard fills SMTP/IMAP automatically. For **GoDaddy / secureserver.net** use
SMTP `smtpout.secureserver.net`, port `465`, *Implicit TLS*; IMAP
`imap.secureserver.net`, port `993`, SSL. Do not use `smtp.secureserver.net` (that relay
requires a whitelisted IP) and never put an `imap.*` host in the SMTP fields — the inbox
checker then fails with `unexpected response: b'220 … SMTPAUTH …'`. Settings warns when
the hosts look swapped.

**New campaign** pre-fills the account, servers, keyring reference and offers *Keep the
current template*, so a new lead list does not reset the email setup.

### Dates

`LastAdvertised` and `LastContacted` accept real datetimes, Excel serial numbers and text
(`2026-04-03`, `03/04/2026`, `3 Apr 2026`, `Apr 3, 2026`, `20260403`).

`DMY`/`MDY` interpret slash dates in that order and **flag genuinely ambiguous values in
the pre-flight report** (`03/04/2026` with both fields ≤ 12). `ISO` accepts only ISO
dates and refuses slash-format values outright instead of guessing. Ambiguous rows are
listed by row number and column.

### Spreadsheet contract

Headers are matched case-insensitively, ignoring spaces, underscores and hyphens; column
order does not matter. Every unlisted column is preserved verbatim, and so is formatting.

| Column | Behaviour |
|---|---|
| `FirstName`, `LastName`, `Company` | Optional, used by placeholders |
| `Email` | **Required** |
| `LastAdvertised` | Program writes ISO date; never moves backwards |
| `Replied` | Program may set TRUE only (one-way); written on every real flush |
| `Ignore` | Read-only; truthy (`y/yes/true/1/x`) means skip |
| `LastContacted` | Read-only |
| `Status`, `LastError`, `Attempts` | Written only if the columns exist |

Write-back is atomic: temp file in the same directory, then `os.replace()`. It refuses to
write while Excel's `~$<name>.xlsx` lock file exists. The workbook is rewritten on every
10 sends, on pause, on stop and on exit — never during a read.

### Switching campaigns

**File → New campaign** and **File → Open campaign** re-import the workbook immediately, so
the contact grid always shows the campaign you just opened. Saving Settings does the same.
A new campaign is written as `campaign.yaml` in the sheet's folder; if one already exists
there, the old `campaign.yaml` and `templates/` are first copied to
`campaign-backup-<timestamp>/`, so the previous campaign is never silently replaced.

## Eligibility

Evaluated in order, first match wins:

1. `Ignore` truthy → `skipped:ignored`
2. on the suppression list → `skipped:suppressed`
3. `Replied` truthy (in the sheet or set by an IMAP-detected reply) → `skipped:replied`
4. invalid email / duplicate of an earlier row → `skipped:invalid` / `skipped:duplicate`
5. no `LastAdvertised` → **eligible**
6. `last_advertised + frequency_days <= today` → **eligible**
7. otherwise → `skipped:too_soon` (with days remaining)

A contact whose last send is `sending` or `unknown` is never re-queued; it is excluded and
surfaced in the review queue.

## Templates

Two kinds, both consumed by the engine as rendered artifacts:

- **blocks** — edited in the builder; source of truth is `templates/<name>.json`. Saving
  regenerates `<name>.html` and `<name>.txt` and rewrites the paths in `campaign.yaml`.
  **Open…** loads any block `.json` into the builder and makes it the campaign's active
  template; **New…** starts from a built-in starter; **Save as…** writes a copy.

Builder features:

- **Line breaks are kept.** Enter inside a paragraph becomes a real `<br>` in HTML and a
  newline in the plain-text part; blank lines stay blank.
- **Per-block alignment**: left, centre, right or justified, for headings, paragraphs,
  lists and signatures; buttons and images get left/centre/right.
- **Blocks**: heading, paragraph, bulleted/numbered list, image (alt, caption,
  click-through, width, alignment), button (label, URL, text/background colour,
  alignment), signature, divider, spacer.
- **Editing**: unlimited undo/redo, duplicate block, drag to reorder (or Alt+↑/↓),
  Delete key when the block list is focused. Ctrl+S save, Ctrl+Shift+S save as, Ctrl+O
  open, Ctrl+D duplicate, Ctrl+B/I/U/K formatting.
- **Template library**: a dropdown of every `.json` in `templates/`, plus **Rename…**
  (renames the file, not just the label) and **History…** (last five saves per template,
  one-click restore).
- **Autosave**: a draft is written every 30 seconds; if Dispatch closes unexpectedly the
  next open offers to restore it.
- **Preview**: desktop (600 px) and mobile (375 px) widths, merged subject and preheader
  with character counts, HTML source view, and `.eml` export.
- **Send test…** accepts several addresses (first is To, the rest are Bcc).
- **Footer…** edits the postal address and unsubscribe links without leaving the builder.
- **Quality checks** run with *Validate*: missing alt text, ALL-CAPS subject, spam-trigger
  phrases, too many links, very short body, unknown placeholders, link text that is just
  a raw URL.
- **Placeholders insert at the cursor** in whichever field has focus.
- **raw** — a hand-written `.html`/`.txt` pair, opened read-only in the builder.

Placeholders: any spreadsheet column by name, plus `{Email}`, `{UnsubscribeURL}`,
`{UnsubscribeToken}`, `{PostalAddress}`. Filters: `|default:"text"`, `|upper`, `|title`,
`|trim` (also `|lower`). Markdown subset inside blocks: `**bold**`, `*italic*`,
`__underline__`, `[label](https://url)`; everything else is escaped and newlines become
`<br>`.

Generated HTML is a single-column table layout with inline styles only — no flexbox, grid,
`<style>`, scripts, web fonts or CSS variables. Every image has `alt`, `width`,
`border="0"` and `display:block`; buttons are bulletproof table-cell links. The plain-text
part is derived from the HTML, converts links to `label (url)` and wraps at 72 characters.

The program appends the compliance footer and sets `List-Unsubscribe` and
`List-Unsubscribe-Post: List-Unsubscribe=One-Click` on every message.

## Logs

The bottom log is filterable, timestamped and exportable to CSV. It records the email
**domain plus a masked local part** (`al***@example.com`) — never bodies. Full addresses
appear only in the table and in explicit CSV exports.

## When Gmail (or anyone) says 550 / 421

**`550 5.1.1` / “user unknown” / 5.x.x recipient rejected**
The address does not exist or refuses mail. Dispatch marks the row `failed_hard`, adds the
address to `suppression` as `hard_bounce`, and never tries it again. Fix the address in
the sheet and remove it from the suppression list if it was a mistake
Open **Tools → Suppression & review…** (also in Settings), select the address and choose
*Remove selected*. The same screen lets you add an address manually, export the list, and
approve opt-out replies.

**`421 4.7.28` / “quota exceeded” / “rate limit”**
The account is sending too fast or too much. Dispatch suspends the account for **10
minutes**, logs it loudly and continues at concurrency 1. If this keeps happening:
lower `limits.hourly_cap`, raise `throttle.random_seconds`, or split the campaign over
several days. A 4xx is temporary — those rows are marked `failed_soft` and can be retried
in a later run.

**`535` authentication failed**
The run stops immediately. Re-save the password (Gmail needs an App Password) in
Settings → Sending account. Dispatch never retries auth failures in a loop.

**`530` / “must issue STARTTLS”**
Toggle `sender.smtp.starttls` or `sender.smtp.ssl` to match your provider (587 + STARTTLS
or 465 + implicit TLS).

**Replies/bounces not appearing**
IMAP host, port and password are separate from SMTP. Use *Re-check inbox* and read the
error in the log. Only messages newer than the last seen UID are parsed; the first pass
looks at the most recent 100.

**“The spreadsheet is open in Excel”**
Close the workbook. Dispatch refuses to write while `~$<name>.xlsx` exists.

**Ambiguous dates in pre-flight**
Pick `DMY` or `MDY`, or rewrite those cells as ISO (`2026-04-03`). Dispatch shows exactly
which rows are ambiguous; it does not silently guess in `ISO` mode.

## Safety model

- Dry run is the default; live sending needs config **and** an explicit confirmation.
- One writer process: a single-instance lock plus one sender worker. The worker class has
  an id and claims from its own run, so N=1 today and N workers later is a config change.
- SQLite is the source of truth during a run. The workbook is imported at start and only
  written on flush/pause/stop/exit; nothing is sent from a live sheet read.
- A message is claimed atomically (`queued → sending`). If the process dies between
  `sending` and `sent`, the row becomes `unknown` on restart, is never resent and appears
  in the review queue.
- Interval is measured send-to-send; a failed send does not reset the timer.
- All sending happens off the UI thread; the UI only reads events.

## Decisions

Where the brief was silent, these are the choices made — and where behaviour differs from
a literal reading, the reason.

1. **Warm-up clock lives in SQLite.** `warmup.first_send_date` is stored in
   `meta.warmup_first_send` (and read from config as a seed) rather than rewriting
   `campaign.yaml` after the first send. Rewriting YAML would destroy the operator's
   comments and formatting on first use.
2. **Dry run never writes the workbook.** Sent dates from a dry run are recorded in SQLite
   for reporting (`sends.dry_run=1`, and the table shows `sent (dry)`), but neither the
   spreadsheet nor `contacts.last_advertised` is touched. Write-back only covers real
   sends, and the same contacts stay eligible for the next run.
3. **Contacts are identified by `email_norm`.** Re-importing a sheet upserts, so send
   history survives; rows no longer present are kept with `in_sheet=0` rather than deleted.
4. **`message_id` is generated at enqueue time**, not at send time, so a crash leaves a
   stable ID that inbox matching can still use.
5. **Schema extensions** beyond the brief: `sends.dry_run`, `sends.attempt_no`,
   `sends.ord`, `contacts.in_sheet`, `contacts.last_contacted`, `contacts.status`,
   `contacts.last_error`, `contacts.attempts`, plus `needs_review` and `meta` tables.
6. **Bounces can move `sent → failed_hard`.** A delivered message that later produces a
   DSN is a hard failure; the state machine allows exactly that one backwards edge.
7. **Soft failures are not retried within the same run.** The row is marked `failed_soft`,
   the account backs off, and the row becomes eligible again in a later run. Retrying
   inside a run risks duplicate delivery for timeouts where the server may already have
   accepted the message.
8. **Feasibility uses the planned quota**, `min(quota, eligible, remaining daily/warm-up
   allowance)`, so a 200 quota with 12 eligible contacts is not reported as an eight-hour
   job.
9. **Unsubscribe tokens** are `sha256(campaign|from|email)[:16]`, stable per address and
   requiring no server. If `unsubscribe_url` is empty, a `mailto:` link is used.
10. **`env:VAR` secrets** are supported alongside the keyring for tests and CI; the default
    and the documented production path is `keyring:`.
11. **Template kind is inferred** from the presence of the `.json` when `template.kind` is
    absent. Switching a raw template to blocks creates a new block document — arbitrary
    HTML is never parsed back into blocks.
12. **The test-send recipient is `sender.from_email`**, not a hardcoded address, so a
    rebranded campaign still sends the test to its own account.
13. **Logs mask the local part** (`al***@example.com`); the table and exported CSVs carry
    full addresses because the operator needs them.
14. **`dispatch init` copies a 12-row sample sheet**, so the app is runnable end-to-end
    (in dry run) immediately after init.
15. **Timezone handling** uses `zoneinfo` + `tzdata`; send timestamps are stored with the
    local UTC offset, so hourly caps and the window are computed in local time.
16. **Suppression has a dedicated screen** (Tools → Suppression & review…), with the
    review queue next to it: remove a mistaken hard bounce, add an address manually,
    approve an opt-out, export the list. Hard bounces are still added automatically.
17. **Pause during a window wait** is honoured at the next loop iteration; pause does not
    freeze the wall clock.
18. **The frozen app is onedir** (faster start, easier to inspect) rather than onefile.
19. **Dry run follows the real timer.** It schedules `next_allowed_at` exactly like a live
    send, so the countdown, pacing and duration are realistic. (An earlier build advanced
    the timer only after real sends, which made dry runs blast the whole queue instantly —
    fixed and covered by `test_dry_run_honours_the_timer`.)
20. **The UI forces a light palette** (`Fusion` + explicit colours) instead of following
    the OS theme. On Windows dark mode, unstyled containers (scroll viewports, wizard
    headers) painted near-black behind dark labels, which made the template builder's
    block fields unreadable. Scroll areas, viewports and wizard pages are also given an
    explicit light background.
21. **`Replied` is written back on every real flush**, including for contacts that did
    not send in that run (a reply can arrive at any time). Only TRUE is ever written.
22. **The pre-flight quota spinner is capped** at `min(eligible, remaining daily/warm-up
    allowance)`, so a run cannot be started that would stop halfway at the cap.
23. **The interface is tuned for a 1280-wide screen**: the main window's minimum width
    is 1179 px (it was 2004 px because of the dry-run banner), table rows are single-line
    and elided, Email stretches while Error stays fixed, internal status tokens are shown
    as plain English, the contact grid has a search box, Settings uses five tabs,
    pre-flight opens with four summary tiles, the top bar carries a progress bar, and the
    onboarding pages are centred in a 560 px column.
24. **Reliability fixes from the audit** (each has a regression test):
    - Pause freezes *before* the next row is claimed — it no longer lets one extra
      message out while the countdown is running.
    - A window further than 24 h away (Friday evening → Monday) is waited for instead of
      ending the run with `window_closed`.
    - A rate-limit failure is reported as `failed_soft` (matching the database), not
      `failed_hard`.
    - Pre-flight judges a run started before the window opens against the window that is
      about to open, not against zero seconds left.
    - Write-back compares existing dates using `campaign.date_order`, and `.xlsm`
      workbooks keep their VBA project.
    - Re-importing a contact that had left the sheet restores its original id, so its
      send history and review items stay attached.
    - The IMAP watermark resets when `UIDVALIDITY` changes, so a recreated mailbox does
      not hide replies forever.
    - Opt-out scanning ignores quoted text, so our own unsubscribe footer in a quoted
      reply no longer looks like an opt-out.
    - The single-instance lock uses Qt's staleness check instead of never expiring (a
      crash no longer locks the app out permanently).
    - UI timers stop on close, and statistics never raise after the database is closed.
    - A live pre-flight blocks on a placeholder SMTP host, a missing keyring password or
      a missing postal address.
    - Formulas in a date column are reported in pre-flight (an uncached formula reads as
      "never advertised" and could otherwise cause a duplicate send).

### Not exercised here

No real mailbox was available, so live SMTP/IMAP against a provider was not run. The send
loop is tested against a localhost aiosmtpd server, the monitor against saved DSN/reply
fixtures, and the keyring round-trip against Windows Credential Locker. `campaign.yaml`
still contains `smtp.PROVIDER` / `imap.PROVIDER` placeholders — replace them (or use the
wizard presets) before a live run.
